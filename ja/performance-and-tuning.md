# 高度な/診断

## チューニングを整理する

高度な/診断 は、メイン パネルを煩雑にすることなく **OrganizeFilesEngine** オプションを公開します。

整理モードでは、重複排除、宛先インデックス、一意の日付ルール、移動および列挙スレッドを調整できます。 BFS 補足、再開状態ファイル、および追加の固有ルート。

修復では、ネットワークとディスクフルの再試行タイミング、オプションの完全なビデオ チェック用に検出されたグラフィックス ハードウェア レーン、ハッシュ読み取りバッファー、および JSON ハートビートのみが維持されます。他のフィールドはコンテキストに対して表示されますが、無効になっています。

ソースまたは出力が有効な場合 NAS または UNC パス、並列処理の低下、ネットワークの再試行を有効のままにし、補足を残す BFS 奇数の SMB ツリーの場合はオンにし、ハッシュが遅い場合は 8 MiB のハッシュ バッファを試してください。

# 詳細/診断 - 各オプション

## この章について

これらのコントロールはエンジンのオプションです。デスクトップ（Windows、macOS、Linux）、Android、iOS、コマンドライン ツールは同じ値を読み取ります。

**整理** モードでは、UI がグレー表示にしないかぎり、以下のすべてのコントロールが使われます。**修復** で使われるのは、ネットワーク再試行、ディスク満杯時の再試行、検出されたグラフィックス ハードウェア レーン（フル ビデオ チェック付き）、ハッシュ読み取りバッファー、ハートビート JSON、**再開状態ファイル**、**新しく開始します (再開状態ファイルを切り詰めます)** だけです。ほかのフィールドは表示されたままですが、修復中は無視されます。

## ネットワークソース

(NAS / UNC) ソースまたは出力がオンの場合 SMB/CIFS 株式、 NAS ボリューム、またはマップされたドライブについては、このセクションを注意深く確認してください。

- **調整する理由** — ローカル SSD で動作するスレッド数により、ファイラーが停止したり過負荷になる可能性があります。
- **試行内容** — ネットワークの再試行をオンのままにします。タイムアウト時の移動スレッドと enum 並列最大値を下げます。フルカウントがそれなしで検証されない限り、補足 BFS はオンのままにします。ネットワーク上でのハッシュが遅い場合は、8 MiB のハッシュ バッファを試してください。
- **ネットワーク待機を無効にする** — 一時的なネットワーク エラーが発生すると高速に失敗します。 Wi-Fi やビジーな共有では危険です。

## 重複排除モード

エンジンが

2 つのファイルが重複していると判断する方法。

| モード | 何をするのか | いつ使用するか | トレードオフ |
| ---- | ------------ | ----------- | --------- |
| **ハッシュ(SHA-256)** | 含まれているすべてのソース ファイルの完全なコンテンツを読み取り、ハッシュし、同一のバイトをグループ化します。 | 最強の実践モード。ソースでの削除（重複および問題のあるファイル）には Hash (SHA-256) が必要です。 | 大きな木では最も遅くなるか、 NAS。いかなるアルゴリズムも絶対的な保証として提示されるべきではありません。 |
| **サイズ + 時間 + 名前** | キー = サイズ、UTC 最終書き込みティック、小文字の名前、その後完全 SHA-256 検証。 | 古いメディア フォルダー レイアウトの保守的な互換モード。 | 名前が変更された重複を見逃す可能性があります。重複や問題のあるファイルの削除では絶対に使用しないでください。 |
| **なし** | ファイル間の重複排除はありません。 | 並べ替えのみであり、重複のクリーンアップは行われません。 | 重複はソースに残ります。 |

## 宛先インデックスをスキップ

- **オフ (デフォルト)** — 既存の **一意** 出力をスキャンし、ハッシュする前にインデックスを付けます。同じ出力フォルダーを再利用する場合の方が安全です。
- **オン** — そのスキャンをスキップします。
- **利点** — 巨大な出力ツリーでの高速化。
- **リスク** — より多くの重複コンテンツが Unique 内に存在する可能性があります。

## ユニークの最小年

メディア

レイアウトの **一意** の下にある日付フォルダーの最小暦年。 **理由** — メタデータが間違っている場合に、非常に古いファイルが奇数年のフォルダーに分散されるのを回避します。

## スレッドの移動

宛先が予約された後でファイルを並行して移動します。

- **高速** — ローカル SSD では高速です。
- **下位** — より安全 NAS、USB、または Wi-Fi にマップされたドライブ。

## 分類スレッドとハッシュスレッド

ソーススキャンと SHA-256 重複排除の並列ワーカーです。

- **分類スレッド数** — ファイルの検出と分類。 CLI: `--classify-threads <n>`.
- **ハッシュスレッド** — コンテンツをハッシュ化するワーカー。 CLI: `--hash-threads <n>`.
- **上書き** — 手動の値は整理プロファイルの既定値を上書きします (`--profile`)。

## 列挙型並列最大値

走査中に同時に読み取るフォルダー数の上限。

- **0** = エンジンにまかせます。
- **小さくする** — 多くのフォルダーを一度に読むとき、SMB にかかる負荷が減ります。

## 補足

- **入 (既定)** — 浅く横に広げる追加の走査。
- **理由** — NAS の一部の場所や深い木は、最初の走査では欠けて見えることがあります。
- **切** — それなしで完全なファイル数を確かめたあとにのみ。
- **CLI** — `--no-bfs` でこの走査を止めます。

## 状態ファイルを再開します (オプション) UTF-8

パス。成功した移動は `B64|` 行を追加するので、次回の整理実行では完了したソースをスキップできます。

- **理由** — 停止またはクラッシュ後も長時間のジョブを継続します。
- **デフォルト パス** — 実行時にフィールドが空の場合、エンジンは `Output\_OrganizeMediaLogs\OrganizeFiles.resume.txt` を使用します。**出力** がない場合は、アプリプロファイル配下の `sessions\<id>\resume\OrganizeFiles.resume.txt` を使用します。
- **デスクトップ UI** — マウス選択およびコピー用の読み取り専用パス リスト。再開ファイルがデフォルトの場所にすでに存在する場合、パスは自動的に表示されます。 **参照** はログ フォルダーを選択し、`OrganizeFiles.resume.txt` を追加します。 **削除** はパスをクリアします。空の場合、ヒントは実行時に使用されるパスを示します。

## 新たに開始

**実際の** 編成実行の開始時に再開ファイルを切り捨てます (ドライ ランは切り捨てられません)。 **進行状況とワークスペースを保存**すると、実行開始時に保存された UI スナップショットもクリアされます。 **理由** — 古い再開ログを継続する代わりに、完全な再カウントを強制します。

## 追加の一意のスキャン ルート

一行につき一つのフォルダー。索引に加える **Unique** の木を増やします（古い配置、別のドライブ）。

- **理由** — 重複の整理が、ほかの場所ですでに片付いたファイルを、動かさずに見られるようになります。
- **デスクトップ画面** — 一行ずつ写せる読み取り専用の一覧です。**追加** は選んだフォルダーを末尾に加えます。**削除** は選んだ行を消します（たとえば NAS 上の古い `Uniques` の木）。

## ネットワーク再試行

(秒) / ネットワーク待機を無効にする 一時的なネットワーク I/O を再試行する秒数。

- **理由** — SMB ファイラーはアイドル状態のセッションをドロップします。整理と修理で使用します。
- **ネットワーク待機を無効にする** — 待機を停止し、代わりに失敗します。

## ディスクフルリトライ

(秒) / ディスクフル待機を無効にする 出力ボリュームの容量が不足した場合も同様のパターン。 **理由** — 長時間実行中にディスクを解放する時間がかかるためです。

## 画像処理カードの並列数

内蔵の **完全な動画検査** が入っていて、**見つかった画像処理カードを使う** も入っているときにのみ働きます。**0** より大きい値は、見つかった作り手（NVIDIA、AMD、Intel、Apple、携帯機器）にまたがる並列検査の本数をはっきり決めます。**0** は本数を自動で決めるという意味で、処理装置だけという意味ではありません。処理装置だけで標本を取るには、カードの一覧から **処理装置のみ** を選びます。本数の指定は処理装置でのビット列検査を計画するもので、基本ソフトの動画復号機構を呼び出すものではありません。

- **コマンドラインの既定** — 完全な動画検査が実行されるとき、`--hwaccel <value>` が検査本数の既定（`cpu`、`auto`、`cuda`、`qsv`、`d3d11va`、`dxva2`、`vaapi`、`apple`、`mobile`）を選びます。

## ハッシュ読み取りバッファー

ハッシュ中のワーカーごとの読み取りバッファー (512 KiB、1 MiB、8 MiB)。 **理由** — バッファーが大きいほど、NASや高レイテンシーの共有が応答が遅いときに助けになります。

## 元に戻すジャーナルを記録

実行の出力ルート配下に移動を記録する任意の JSONL ジャーナルです。

- **目的** — 実際の整理実行後に CLI で元に戻せるようにします。
- **アーカイブ** — ジャーナルが有効な間、整理後のアーカイブは無効のままです。
- **CLI** — `--record-undo-journal`（メイン ウィンドウのチェックボックスと同じ）。

## 実行ハートビート JSON

任意の `Organize.Files.run.json` を `Output\_OrganizeMediaLogs` の下に書き出します。

- **理由** — 整理や修復の最中に、外部の道具が生きた数（走査済み、計画済み、完了）を読み取れます。
- **書き出しの間隔** — 情報源の走査中は見たファイル一万件ごと、一致五千件ごと、およそ十五秒ごと、検証・ハッシュ計算・移動の間は千件ごとで最短五秒の間隔、そして大きな段階のたびに書き出します。
