# 고급/진단

## 튜닝 정리

고급/진단은 기본 패널을 어지럽히지 않고 **OrganizeFilesEngine** 옵션을 표시합니다.

정리 모드에서는 중복 제거, 대상 인덱스, 고유 날짜 규칙, 이동 및 열거 스레딩, BFS 보완, 재개 상태 파일 및 추가 고유 루트를 조정할 수 있습니다.

복구는 네트워크 및 디스크 전체 재시도 타이밍, 선택적 전체 비디오 확인을 위해 감지된 그래픽 하드웨어 레인, 해시 읽기 버퍼 및 JSON 하트비트만 유지합니다. 다른 필드는 상황에 따라 표시되지만 비활성화됩니다.

소스 또는 출력이 NAS 또는 UNC 경로에 있는 경우 병렬 처리를 낮추고, 네트워크 재시도를 활성화하고, 홀수 SMB 트리에 대해 보완 BFS를 설정하고, 해싱이 느린 경우 8MiB 해시 버퍼를 사용해 보세요.

# 고급/진단 — 각 옵션

## 이 장 정보

이 컨트롤은 엔진 옵션입니다. 데스크톱(Windows, macOS, Linux), Android, iOS와 명령줄 도구는 같은 값을 읽습니다.

**정리** 모드는 UI가 회색으로 표시하지 않는 한 아래의 모든 컨트롤을 사용합니다. **복구**는 네트워크 재시도, 디스크 가득 참 재시도, 감지된 그래픽 하드웨어 레인(전체 비디오 확인 포함), 해시 읽기 버퍼, 하트비트 JSON, **재개 상태 파일**, **새로 시작(재개 상태 파일 자르기)**만 사용합니다. 다른 필드는 계속 표시되지만 복구 중에는 무시됩니다.

## 네트워크 소스(NAS / UNC) 소스

또는 출력이 SMB/CIFS 공유, NAS 볼륨 또는 매핑된 드라이브에 있는 경우 이 섹션을 주의 깊게 검토하세요.

- **조정해야 하는 이유** — 로컬 SSD에서 작동하는 스레드 수로 인해 파일러가 정지되거나 과부하될 수 있습니다.
- **시도할 사항** — 네트워크 재시도를 유지합니다. 이동 스레드를 낮추고 시간 초과 시 병렬 최대값을 열거합니다. 보충 BFS 없이 전체 카운트가 확인되지 않는 한 보충 BFS를 켜두십시오. 네트워크에서 해싱이 느린 경우 8MiB 해시 버퍼를 사용해 보세요.
- **네트워크 대기 비활성화** — 일시적인 네트워크 오류가 발생하면 빠르게 실패합니다. Wi-Fi 또는 사용량이 많은 공유에서는 위험합니다.

## Dedupe 모드

엔진이 두 파일이 중복되었는지 판단하는 방법입니다.

| 모드 | 그것이 하는 일 | 사용 시기 | 트레이드오프 |
| ---- | ------------ | ----------- | --------- |
| **해시(SHA-256)** | 포함된 모든 소스 파일의 전체 콘텐츠를 읽고 해시한 다음 동일한 바이트를 그룹화합니다. | 최강의 실용 모드. 원본에서 삭제하려면 Hash (SHA-256)가 필요합니다 (중복 및 문제 파일). | 큰 나무 또는 NAS에서 가장 느립니다. 어떠한 알고리즘도 절대적인 보장으로 제시되어서는 안 됩니다. |
| **크기 + 시간 + 이름** | 키 = 크기, UTC 마지막 쓰기 틱, 소문자 이름, 전체 SHA-256 확인. | 이전 미디어 폴더 레이아웃에 대한 보수적 호환성 모드입니다. | 이름이 변경된 중복 항목을 놓칠 수 있습니다. 중복 삭제나 문제 파일 삭제와 함께 사용하지 마십시오. |
| **없음** | 파일 간 중복 제거가 없습니다. | 중복 정리가 아닌 정렬만 가능합니다. | 중복은 소스에 남아 있습니다. |

## 대상 인덱스

- **끔 (기본값)** — 이미 있는 **Unique** 출력을 훑어 해시 이전에 색인해 둡니다. 같은 출력 폴더를 다시 쓸 때 더 안전합니다.
- **켬** — 그 훑기를 건너뜁니다.
- **이득** — 출력 트리가 클수록 빨라집니다.
- **위험** — 중복된 내용이 **Unique** 안으로 더 많이 들어올 수 있습니다.

## 고유 최소 연도

미디어 레이아웃의 **고유** 아래에 있는 날짜 폴더의 최소 달력 연도입니다. **이유** — 메타데이터가 잘못된 경우 아주 오래된 파일을 홀수 연도 폴더에 흩어놓는 것을 방지합니다.

## 이동 스레드

대상이 예약된 후 병렬 파일을 이동합니다.

- **더 높음** — 로컬 SSD에서 더 빠릅니다.
- **낮음** — NAS, USB 또는 Wi-Fi 매핑 드라이브에서 더 안전합니다.

## 분류 및 해시 스레드

소스 검사와 SHA-256 중복 제거 중의 병렬 작업자입니다.

- **분류 스레드** — 파일 검색 및 분류. CLI: `--classify-threads <n>`.
- **해시 스레드** — 콘텐츠 해싱 작업자. CLI: `--hash-threads <n>`.
- **재정의** — 수동 값은 정리 프로필 기본값을 재정의합니다 (`--profile`).

## 열거형 병렬 최대

스캔 중 병렬로 나열할 디렉터리 수의 상한입니다.

- **0** = 엔진 자동.
- **낮음** — 한 번에 많은 폴더가 나열되면 SMB에 대한 부담이 줄어듭니다.

## BFS 디렉토리 패스

- **켬 (기본값)** — 얕게 옆으로 훑는 한 번의 추가 통과.
- **이유** — 일부 NAS 경로나 깊은 트리는 첫 통과만으로는 덜 채워진 것처럼 보입니다.
- **끔** — 그것 없이도 파일 수가 온전함을 확인한 뒤에만.
- **CLI** — `--no-bfs` 가 이 통과를 끕니다.

## 재개 상태 파일

선택적 UTF-8 경로. 성공적인 이동은 `B64|` 줄을 추가하므로 다음 정리 실행에서는 완료된 소스를 건너뛸 수 있습니다.

- **이유** — 중지 또는 충돌 후에도 긴 작업을 계속합니다.
- **기본 경로** — 런타임 시 필드가 비어 있으면 엔진은 `Output\_OrganizeMediaLogs\OrganizeFiles.resume.txt`를 사용합니다. 출력이 없으면 앱 프로필에서 `sessions\<id>\resume\OrganizeFiles.resume.txt`를 사용합니다.
- **데스크톱 UI** — 마우스 선택 및 복사를 위한 읽기 전용 경로 목록입니다. 기본 위치에 재개 상태 파일이 이미 존재하는 경우 경로가 자동으로 나타납니다. **찾아보기**는 로그 폴더를 선택하고 `OrganizeFiles.resume.txt`를 추가합니다. **제거**는 경로를 지웁니다. 비어 있으면 런타임에 사용되는 경로가 힌트에 표시됩니다.

## 새로

시작 **실제** 정리 실행이 시작될 때 재개 파일을 자릅니다(드라이런은 자르지 않습니다). **진행 상황 및 작업 영역 저장**을 사용하면 실행 시작 시 저장된 UI 스냅샷도 지웁니다. **이유** — 이전 재개 로그를 계속하는 대신 전체 재검토를 강제합니다.

## 추가 고유 스캔 루트

한 줄에 하나의 폴더: 색인을 생성할 추가 **고유** 트리(레거시 레이아웃, 기타 볼륨).

- **이유** — Dedupe는 파일을 다시 이동하지 않고도 이미 다른 곳에 정리된 파일을 볼 수 있습니다.
- **데스크톱 UI** — 줄당 복사에 대한 읽기 전용 목록입니다. **추가**는 선택한 폴더를 추가합니다. **제거**는 선택한 줄을 삭제합니다(예: NAS의 이전 `Uniques` 트리).

## 네트워크 재시도(초) / 네트워크 대기 비활성화 임시

네트워크 I/O를 재시도하는 데 걸리는 시간(초)입니다.

- **이유** — SMB 파일러는 유휴 세션을 삭제합니다. 정리하고 수리하는데 사용됩니다.
- **네트워크 대기 비활성화** — 대기를 중지하고 대신 실패합니다.

## 디스크 가득 참 재시도(초) / 디스크 가득

참 대기 비활성화 출력 볼륨의 공간이 부족할 때에도 동일한 패턴입니다. **이유** — 장기간 실행 중에 디스크를 확보할 시간입니다.

## 그래픽 카드의 병렬 갈래

내장 **전체 동영상 검사** 가 켜져 있고 **찾아낸 그래픽 카드 사용** 도 켜져 있을 때에만 쓰입니다. **0** 보다 큰 값은 찾아낸 제조사(NVIDIA, AMD, Intel, Apple, 모바일)에 걸쳐 나란히 검사할 갈래 수를 못박습니다. **0** 은 갈래 수를 스스로 알아낸다는 뜻이며, 처리 장치만 쓴다는 뜻이 아닙니다. 처리 장치만으로 표본을 뜨려면 그래픽 카드 목록에서 **CPU 만** 을 고르십시오. 갈래 표시는 처리 장치에서 하는 비트열 검사를 계획할 뿐, 운영 체제의 하드웨어 동영상 복호를 부르지 않습니다.

- **명령줄 기본값** — 전체 동영상 검사가 돌 때 `--hwaccel <value>` 가 검사 갈래의 기본값(`cpu`, `auto`, `cuda`, `qsv`, `d3d11va`, `dxva2`, `vaapi`, `apple`, `mobile`)을 고릅니다.

## 해시 읽기 버퍼

해시 중 작업자별 읽기 버퍼(512KiB, 1MiB, 8MiB). **이유** — 버퍼가 클수록 NAS나 고지연 공유가 응답이 느릴 때 도움이 됩니다.

## 실행 취소 저널 기록

실행의 출력 루트 아래 이동을 기록하는 선택적 JSONL 저널입니다.

- **목적** — 실제 정리 실행 후 CLI에서 실행 취소를 지원합니다.
- **보관** — 저널이 활성인 동안 정리 후 보관은 꺼진 상태로 유지됩니다.
- **CLI** — `--record-undo-journal`(주 창의 확인란과 동일).

## 실행 하트비트 쓰기 JSON은

선택 사항인 `Organize.Files.run.json` 을 `Output\_OrganizeMediaLogs` 아래에 씁니다.

- **이유** — 정리나 복구가 진행되는 동안 바깥 도구가 살아 있는 계수(훑음, 계획, 완료)를 읽을 수 있습니다.
- **기록 간격** — 출처를 훑는 동안 본 파일 1만 개마다, 일치 5천 건마다, 약 15초마다, 검증과 해싱, 이동 중에는 파일 1천 개마다 많아야 5초에 한 번, 그리고 큰 단계마다 씁니다.
