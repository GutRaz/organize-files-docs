# AI-помощник (MCP)

Команды с лицензией подключают **OrganizeFiles.Cli** к Claude Desktop, **Cursor**, VS Code Copilot или другому клиенту Model Context Protocol, далее клиенту MCP. Коннектор — это пакет Python **organize-files-mcp**. Его можно бесплатно скачать с github.com/GutRaz/organize-files-docs, из папки `mcp/`.

**В настольном приложении:** откройте **Настройка MCP…** в группе **Приложение и данные** в столбце параметров или в меню инструментов. Выберите **Доступ к MCP**: **Выкл.**, **Монитор** или **Управление**. Затем скопируйте фрагмент JSON. После каждой смены уровня перезагрузите MCP в приложении ИИ, потому что **Управление** каждый раз создаёт новый токен.

**Спросите помощника по документации** «setup mcp» или «cum setez mcp», чтобы получить шаги для текущей системы.

## Уровни доступа к MCP, задаются в приложении

Уровни соответствуют трём видам работы: **чтение / предпросмотр / выполнение**.

| Уровень | Вид работы | Что может ИИ |
|-------|--------|-------------------|
| **Выкл.** | — | Только `organize_mcp_status`. Нет диагностики и нет доступа к рабочему пространству. |
| **Монитор** | **Чтение** | Всё, что есть в Выкл., а также диагностика только для чтения, история запусков и заданий, блокировки, проверки аудита, **`organize_capabilities`** и **`organize_workspace_snapshot`**. `organize_capabilities` перечисляет режимы запуска, среди них **`ai`**, области перемещения и цели. `organize_workspace_snapshot` показывает рабочее пространство, сохранённое в главном окне. Нет предпросмотра и нет выполнения. |
| **Управление** | **Предпросмотр** / **Выполнение** | Всё, что есть в Монитор, а также **`organize_create_job`**, **`organize_run_workspace`** и **`organize_remove_empty_organize_layout`**. Нужен **токен управления** в настройках MCP, `ORGANIZE_FILES_MCP_CONTROL_TOKEN`. **Предпросмотр** — это `organize_run_workspace`, когда в сохранённом рабочем пространстве включён **Пробный запуск**, поэтому ничего не записывается. **Выполнение** — тот же инструмент с выключенным Пробным запуском, поэтому файлы перемещаются. Коннектор не передаёт `--confirm-destructive`, если вызов не задаёт `confirm_destructive=true`, а без этого флага командная строка отказывает с `confirm_destructive_required`. |

Файл управления — **`mcp-control.json`**, рядом с `automation-jobs.json` в папке профиля приложения. Скопированный фрагмент его не называет, потому что коннектор находит файл в папке профиля по умолчанию. Задавайте **`ORGANIZE_FILES_MCP_CONTROL_FILE`** только тогда, когда файл лежит в другом месте. На уровне **Управление** фрагмент также задаёт **`ORGANIZE_FILES_ALLOW_APP_TARGET=1`**.

**Перемещение и удаление требуют второго шага, который делает человек.** Помощник сам ставит своё подтверждение, поэтому прочитанный текст мог бы склонить помощника к подтверждению. Поэтому запуск, который не является пробным, требует ещё и окна, открытого в **Настройка MCP**, и это окно само закрывается через 15 минут. Вне окна помощник по-прежнему может подготовить запуск и показать предпросмотр, но сам запуск отклоняется. И файл управления, и окно подписаны ключом этой установки. Файл управления, изменённый вручную или скопированный с другого компьютера, считается уровнем Выкл.

## Инструменты MCP по уровням

**Всегда, в том числе на Выкл.:** `organize_mcp_status`

**Монитор и Управление:** `organize_server_info`, `organize_cli_help`, `organize_query_runs`, `organize_show_run`, `organize_list_running`, `organize_query_jobs`, `organize_due_pass_lock_status`, `organize_output_lock_status`, `organize_verify_audit`, `organize_exit_code_guide` и `organize_run_raw_cli`, который принимает только команды для чтения.

**Также в Монитор и Управление:** `organize_capabilities`, который показывает режим запуска **`ai`** для файлов ИИ и машинного обучения, и `organize_workspace_snapshot`.

**Только Управление:** `organize_create_job` из рабочего пространства или из JSON задания, `organize_run_workspace` для предпросмотра или настоящего запуска, как указывает Пробный запуск рабочего пространства, и `organize_remove_empty_organize_layout`, который удаляет пустые папки раскладки внутри существующей папки вывода и никогда не создаёт саму папку вывода.

Команды, которые перемещают или удаляют файлы, через MCP всегда заблокированы вне уровня **Управление**. Никакая другая настройка их не разрешает.

## Флаги командной строки, которые использует коннектор

| Флаг | Уровень | Назначение |
|------|-------|---------|
| `--mcp-control-status` | любой | JSON с уровнем, путём к файлу управления и флагами Монитор и Управление |
| `--mcp-capabilities` | Монитор и выше | Список JSON с режимами запуска, среди них **`ai`**, областями перемещения и целями |
| `--mcp-workspace-snapshot` | Монитор и выше | Сохранённое рабочее пространство и то, как оно становится заданием |
| `--mcp-create-job` | Управление | Создать задание с `--from-workspace` или `--mcp-job-json` |
| `--mcp-run-workspace` | Управление | Запустить сохранённое рабочее пространство с `--allow-app-target` и `--mcp-control-token` |
| `--remove-empty-organize-layout` | Управление | Удалить пустые папки раскладки внутри существующего `--output` |
| `--confirm-destructive` | Управление | Нужен с `--mcp-run-workspace` для запуска, который перемещает или удаляет. Коннектор передаёт его только при `confirm_destructive=true` |

## Настройки в JSON клиента MCP

| Настройка | Когда |
|----------|------|
| `ORGANIZE_FILES_CLI` | Путь к OrganizeFiles.Cli |
| `ORGANIZE_FILES_JOBS_FILE` | Путь к `automation-jobs.json` |
| `ORGANIZE_FILES_MCP_CONTROL_FILE` | Путь к `mcp-control.json`, только если файл не в папке профиля по умолчанию |
| `ORGANIZE_FILES_MCP_CONTROL_TOKEN` | Только уровень **Управление**, из фрагмента приложения |
| `ORGANIZE_FILES_ALLOW_APP_TARGET` | Уровень **Управление**, для запусков сохранённого рабочего пространства |
| `ORGANIZE_FILES_MCP_READ_TOKEN` | Необязательно. Тот же токен, который хост использует для операций чтения |

## Настройка в Windows

1. **Python 3.10 или новее** — выполните `python -V` в PowerShell. Если Python нет или версия старше, установите его с [python.org](https://www.python.org/downloads/) и отметьте **Add python.exe to PATH**.
2. **Скачайте и установите коннектор** — скачайте github.com/GutRaz/organize-files-docs как ZIP, распакуйте и запустите `powershell -ExecutionPolicy Bypass -File mcp\Install-OrganizeFilesMcp.ps1`. Скрипт создаёт отдельную среду Python для коннектора и выводит команду для приложения ИИ.
3. **В приложении:** **Настройка MCP…**, выберите **Монитор** или **Управление**, затем скопируйте JSON.
4. **Пути:** в `%LocalAppData%\OrganizeFilesCrossPlatform\` лежат задания и `mcp-control.json`. Cursor: `%USERPROFILE%\.cursor\mcp.json`. Claude: `%APPDATA%\Claude\claude_desktop_config.json`. VS Code: `%USERPROFILE%\.vscode\mcp.json`.
5. **Проверка** — выполните `organize_mcp_status`, затем `organize_server_info`. `cliResolved` должно быть true, а `mcpLevel` должен совпадать с приложением.

## Настройка в macOS

Те же шаги с **python3** и `bash mcp/install-organize-files-mcp.sh`. Если `python3 -V` показывает 3.9 или Python нет вовсе, сначала установите Python с [python.org](https://www.python.org/downloads/macos/). Пути: `~/Library/Application Support/OrganizeFilesCrossPlatform/`, `~/.cursor/mcp.json`, Claude `~/Library/Application Support/Claude/claude_desktop_config.json`.

## Настройка в Linux

Те же шаги с **python3** и `bash mcp/install-organize-files-mcp.sh`. В Debian и Ubuntu сначала выполните `sudo apt install python3-venv`. Пути: `~/.local/share/OrganizeFilesCrossPlatform/`, или `$XDG_DATA_HOME`, если он задан, `~/.cursor/mcp.json`, Claude `~/.config/Claude/claude_desktop_config.json`.

## Безопасность

- MCP работает от имени **локального пользователя** операционной системы, с теми же правами, что и командная строка, запущенная вручную.
- Храните **токен управления** и **токен чтения** в секрете, как пароли. Скопируйте JSON заново после включения уровня Управление.
- **`organize_run_workspace`** работает в командной строке, а не через кнопку Запуск в приложении. Не запускайте два задания на одну и ту же папку вывода одновременно.
- Примеры: `mcp/examples/`.

## Запуски, которые перемещают или удаляют

`--mcp-run-workspace` требует `--confirm-destructive` для каждого запуска, который не является пробным, будь то перемещение, удаление или архивирование. Без этого флага командная строка отвечает `confirm_destructive_required`. Коннектор не передаёт флаг, если вызов не задаёт `confirm_destructive=true`, а это может только уровень Управление. Поэтому по умолчанию коннектор отказывает.

## Языки

Ответы о настройке берутся из того же переведённого руководства, что и окно Документация и Помощник по руководству. `organize_capabilities` сообщает режимы запуска и цели, а не названия тем приложения.
