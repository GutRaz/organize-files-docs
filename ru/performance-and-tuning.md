# Дополнительно / Диагностика

## Организовать тюнинг

Дополнительно/Диагностика предоставляет параметры **OrganizeFilesEngine**, не загромождая главную панель.

Режимы организации позволяют настраивать дедупликацию, индекс назначения, правила уникальных дат, потоки перемещения и перечисления, дополнение BFS, файл возобновления и дополнительные уникальные корни.

При восстановлении сохраняется только время повторных попыток заполнения сети и диска, обнаруженные линии графического оборудования для дополнительной полной проверки видео, буфер чтения хэша и контрольный сигнал JSON. Другие поля видны для контекста, но отключены.

Когда источники или выходные данные находятся на путях NAS или UNC, уменьшите параллелизм, включите повторную попытку сети, оставьте дополнение BFS включенным для нечетных деревьев SMB и попробуйте хеш-буфер размером 8 МБ, если хеширование происходит медленно.

# Дополнительно/Диагностика — каждый вариант

## Об этой главе

Эти элементы управления — параметры движка. Настольное приложение (Windows, macOS, Linux), Android, iOS и инструмент командной строки читают одни и те же значения.

В режимах **Организации** используются все указанные ниже элементы управления, если интерфейс их не затеняет. **Восстановление** использует только повтор при сетевой ошибке, повтор при заполненном диске, обнаруженные линии графического оборудования (с полной проверкой видео), буфер чтения хеша, JSON пульса, **Файл состояния возобновления** и **Начать заново (обрезать файл возобновления)**. Остальные поля остаются видимыми, но во время восстановления игнорируются.

## Сетевые источники (NAS / UNC)

Если источники или выходные данные находятся на общих ресурсах SMB/CIFS, томах NAS или подключенных дисках, внимательно просмотрите этот раздел.

- **Зачем настраивать** — количество потоков, работающих на локальном SSD, может привести к остановке или перегрузке файлового механизма.
- **Что попробовать** — оставьте повторную попытку подключения к сети включенной. Нижние потоки перемещения и перечисление параллельного максимума по таймаутам. Оставьте дополнение BFS включенным, если без него не будет проверен полный подсчет. Попробуйте хэш-буфер размером 8 МБ, если хеширование по сети происходит медленно.
- **Отключить ожидание сети** — быстрый сбой при временных сетевых ошибках. Рискованно использовать Wi-Fi или занятые общие ресурсы.

## Режим дедупликации

Как механизм определяет, что два файла являются дубликатами.

| Режим | Что он делает | Когда использовать | Компромисс |
| ---- | ------------ | ----------- | --------- |
| **Хеш (SHA-256)** | Считывает и хеширует полное содержимое каждого включенного исходного файла, затем группирует идентичные байты. | Самый сильный практический режим. Hash (SHA-256) обязателен для удаления на месте (дубликаты и проблемные файлы). | Медленнее всего на больших деревьях или NAS. Ни один алгоритм не должен представляться как абсолютная гарантия. |
| **Размер + время + имя** | Ключ = размер, тики последней записи в формате UTC, имя в нижнем регистре, затем полная проверка SHA-256. | Консервативный режим совместимости со старыми макетами папок мультимедиа. | Может пропустить переименованные дубликаты. Никогда не используйте с удалением дубликатов или проблемных файлов. |
| **Нет** | Никакой межфайловой дедупликации. | Только сортировка, а не дублирующая очистка. | Дубликаты остаются в источниках. |

## Пропустить индекс

- **Выключено (по умолчанию)** — Обходит имеющийся вывод **Unique** и заносит его в указатель до хеширования. Безопаснее при повторном использовании той же выходной папки.
- **Включено** — Пропускает этот обход.
- **Выгода** — Быстрее на очень больших выходных деревьях.
- **Риск** — Внутрь **Unique** может попасть больше повторяющегося содержимого.

## Мин. год для папки Уникальные

Минимальный календарный год для папок с датами в разделе **Уникальный** в макетах мультимедиа. **Почему** — позволяет избежать разбрасывания очень старых файлов по папкам нечетного года, если метаданные неверны.

## Перемещение потоков

Параллельное перемещение файлов после того, как места назначения зарезервированы.

- **Выше** — быстрее на локальном SSD.
- **Ниже** — безопаснее на подключенных дисках NAS, USB или Wi-Fi.

## Потоки классификации и хеширования

Параллельные обработчики при сканировании источников и дедупликации SHA-256.

- **Потоки классификации** — Обнаружение и классификация файлов. CLI: `--classify-threads <n>`.
- **Хэш-потоки** — Обработчики хеширования содержимого. CLI: `--hash-threads <n>`.
- **Переопределения** — Ручные значения переопределяют значения профиля (`--profile`).

## Перечисление параллельного максимума

Ограничение для параллельного просмотра каталогов во время сканирования.

- **0** = двигатель автоматический.
- **Ниже** — меньшая нагрузка на SMB при одновременном отображении большого количества папок.

## Дополнение BFS проход по

- **Включено (по умолчанию)** — Дополнительный неглубокий проход вширь.
- **Зачем** — Некоторые пути на NAS и глубокие деревья после первого прохода выглядят неполными.
- **Выключено** — Только после того, как полное число файлов подтверждено без него.
- **CLI** — `--no-bfs` выключает этот проход.

## Файл состояния возобновления

Необязательный путь UTF-8. При успешных перемещениях добавляются строки `B64|`, поэтому при следующем запуске организации можно пропустить готовые исходные коды.

- **Почему** — Продолжение длительной работы после остановки или сбоя.
- **Путь по умолчанию** — если во время выполнения поле пусто, движок использует `Output\_OrganizeMediaLogs\OrganizeFiles.resume.txt`. Без вывода он использует `sessions\<id>\resume\OrganizeFiles.resume.txt` в профиле приложения.
- **Интерфейс рабочего стола** – список путей для выбора и копирования с помощью мыши, доступный только для чтения. Если файл возобновления уже существует в расположении по умолчанию, путь отображается автоматически. **Обзор** выбирает папку журнала и добавляет к ней `OrganizeFiles.resume.txt`. **Удалить** очищает путь. Если оно пусто, подсказка показывает путь, используемый во время выполнения.

## Начать заново

Усекает файл возобновления при запуске **реального** организационного прогона (пробный прогон не усекается). Функция **Сохранить ход выполнения и рабочую область** также удаляет сохраненный снимок пользовательского интерфейса при запуске. **Почему** — Принудительно провести полный пересчет вместо продолжения ведения старого журнала возобновления.

## Дополнительные уникальные

Одна папка в строке: дополнительные деревья **Unique** для указателя (старая раскладка, другой том).

- **Зачем** — Отсев повторов видит файлы, уже упорядоченные в другом месте, и не переносит их снова.
- **Оболочка рабочего стола** — Список только для чтения, чтобы копировать построчно. **Добавить** дописывает выбранную папку. **Удалить** убирает выделенную строку (например, старое дерево `Uniques` на NAS).

## Повторная попытка сети (секунды)

Сколько секунд повторять попытки при кратковременных сбоях сети.

- **Зачем** — Серверы SMB сбрасывают простаивающие сеансы. Используется при упорядочивании и починке.
- **Отключить ожидание сети** — Перестать ждать и сообщить об ошибке.

## Повторная попытка заполнения

диска (секунды) / Отключить ожидание

заполнения диска. Тот же шаблон, когда на выходном томе заканчивается место. **Почему** — Время освободить диск при длительных запусках.

## Полосы видеокарты

Только когда встроенная **полная проверка видео** включена и **Использовать найденную видеокарту** тоже. Значение больше **0** задаёт явное число полос для одновременной проверки среди найденных изготовителей (NVIDIA, AMD, Intel, Apple, мобильные). **0** означает, что число полос определяется само. Это не означает «только процессор». Чтобы брать пробы только на процессоре, выберите в списке видеокарт **Только процессор**. Метки полос планируют проверку потока битов на процессоре. Они не вызывают аппаратное декодирование видео в системе.

- **Заготовка для командной строки** — `--hwaccel <value>` выбирает заготовку полос проверки (`cpu`, `auto`, `cuda`, `qsv`, `d3d11va`, `dxva2`, `vaapi`, `apple`, `mobile`), когда идёт полная проверка видео.

## Буфер чтения хэша

Буфер чтения для каждого работника во время хеширования (512 КиБ, 1 МиБ, 8 МиБ). **Почему** — Большие буферы помогают при медленном ответе NAS или общего ресурса с высокой задержкой

## Записывать журнал отмены

Необязательный журнал JSONL перемещений в корне вывода для запуска.

- **Зачем** — Позволяет отменить через CLI после реального запуска.
- **Архив** — Архивация после упорядочивания остаётся выключенной, пока журнал активен.
- **CLI** — `--record-undo-journal` (то же, что и флажок в главном окне).

## Запись сердечного ритма JSON

Записывает необязательный файл `Organize.Files.run.json` в `Output\_OrganizeMediaLogs`.

- **Зачем** — Внешние средства могут читать живые счётчики (просмотрено, запланировано, завершено) во время упорядочивания или починки.
- **Периодичность** — На каждые 10 000 увиденных файлов, каждые 5000 совпадений и примерно каждые 15 секунд при обходе источников, после каждых 1000 файлов и не чаще раза в 5 секунд при проверке, хешировании и перемещениях и на каждом крупном этапе.
