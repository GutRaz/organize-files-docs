# การเฝ้าระวังด้วย Prometheus และ Grafana

## ตัวนับครอบคลุมอะไรบ้าง

งานที่กำหนดเวลาไว้เก็บชุดตัวนับและมาตรวัดของ Prometheus ไว้จำนวนไม่มาก ทุกชื่อขึ้นต้นด้วย `organize_files_automation_` และทั้งชุดถูกเผยแพร่เป็นข้อความแบบ Prometheus โฮสต์ทั้งสามที่รันงานต่างเผยแพร่ชุดเดียวกัน ได้แก่ โปรแกรมบนเดสก์ท็อป บริการ `OrganizeFiles.JobAgent` และโฮสต์บรรทัดคำสั่งที่ใช้ภายในคอนเทนเนอร์

ตัวนับอธิบายตัวจัดกำหนดการ ไม่ได้อธิบายไฟล์ สิ่งที่นับคือรอบตรวจ ผลของงาน การอนุมัติ การส่ง webhook และการจัดระเบียบประวัติ ไม่มีการนับสิ่งใดเกี่ยวกับไฟล์ที่งานย้าย

## ส่งออกเป็นไฟล์โดยไม่เปิดพอร์ต

`automation-metrics.prom` ถูกเขียนลงในโฟลเดอร์ข้อมูลของระบบอัตโนมัติ ข้าง ๆ `automation-jobs.json` และถูกเขียนใหม่หลังรอบตรวจที่ถึงกำหนดทุกครั้งและทุกครั้งที่มีการอ่าน รูปแบบคือรูปแบบที่ตัวเก็บ textfile ของ `node_exporter` อ่าน ดังนั้นเครื่องที่รัน `node_exporter` อยู่แล้วจึงถูกครอบคลุมโดยไม่ต้องมีพอร์ตที่คอยฟัง ไม่ต้องมีโทเคน และไม่ต้องมีกฎไฟร์วอลล์ ไฟล์ถูกแทนที่ในคราวเดียว และลิงก์สัญลักษณ์ที่ทิ้งไว้แทนที่ไฟล์จะหยุดการเขียนแทนที่จะถูกเดินตาม

## จุดอ่านค่า

จุดอ่านค่ามีอยู่ก็ต่อเมื่อ `ORGANIZE_FILES_METRICS_HTTP_PORT` เก็บพอร์ตระหว่าง 1 ถึง 65535 หากไม่มีตัวแปรนั้นก็ไม่มีอะไรคอยฟัง

| ตัวแปร | ผล |
| -------- | ------ |
| `ORGANIZE_FILES_METRICS_HTTP_PORT` | พอร์ตที่จะคอยฟัง หากขาดไปหรืออยู่นอกช่วง ก็ไม่มีจุดอ่านค่าเลย |
| `ORGANIZE_FILES_METRICS_HTTP_BIND` | ที่อยู่ที่คอยฟัง ค่าปริยายคือ `127.0.0.1` ค่า `0.0.0.0`, `+` และ `*` หมายถึงทุกที่อยู่ ส่วนค่าอื่นจะย้อนกลับไปเป็น `127.0.0.1` |
| `ORGANIZE_FILES_METRICS_BEARER_TOKEN` | โทเคน bearer ที่ต้องมีบน `/metrics` และบน `/ready` |
| `ORGANIZE_FILES_METRICS_READY_PUBLIC` | `1` ปล่อยให้ `/ready` ตอบได้โดยไม่ต้องใช้โทเคนนั้น เพื่อการตรวจของคลัสเตอร์ เส้นทางของโฮสต์จะถูกตัดออกจากคำตอบ |
| `ORGANIZE_FILES_READY_FAIL_ON_DUE_PASS_EXIT_CODES` | รหัสสิ้นสุดคั่นด้วยจุลภาคที่ทำให้ `/ready` รายงานว่ายังไม่พร้อม แทนที่รายการที่ติดมาในตัว |
| `ORGANIZE_FILES_READY_IGNORE_LAST_DUE_EXIT` | `1` ไม่สนใจรหัสสิ้นสุดของรอบตรวจล่าสุด และไม่สนใจสภาพก่อนที่รอบแรกจะจบด้วย |
| `ORGANIZE_FILES_READY_JSON` | `1` บังคับให้เนื้อหาบน `/ready` เป็น JSON แม้กับผู้เรียกที่ขอข้อความล้วน |

ที่อยู่นอกวงลูปแบ็กจะถูกปฏิเสธก่อนเปิดตัวคอยฟัง หากยังไม่ได้ตั้งโทเคน bearer การปฏิเสธถูกเขียนลงช่องทางข้อผิดพลาดและถูกส่งเป็นเหตุการณ์ webhook เพราะการผสมแบบนั้นจะยกตัวนับให้ทั้งเครือข่าย

## เส้นทางที่ให้บริการ

- `/metrics` — ตัวนับในรูปข้อความแบบ Prometheus คำขอไปยัง `/` คืนเนื้อหาเดียวกัน
- `/ready` — ความพร้อมสำหรับตัวจัดวางระบบ คำตอบคือ `200` ทันทีที่โฟลเดอร์ระบบอัตโนมัติรับการเขียนทดสอบ ไฟล์งานเปิดได้ โฟลเดอร์ประวัติคลี่ออกภายในรากข้อมูล และรอบตรวจที่ถึงกำหนดรอบล่าสุดจบด้วยรหัสสิ้นสุดที่ไม่ขวาง มิฉะนั้นคำตอบคือ `503` พร้อมเหตุผลสั้น ๆ เช่น `due_pass_not_completed` หรือ `last_due_pass_license_failed`
- `/health` — เป็นเพียงสัญญาณว่ายังมีชีวิต เส้นทางนี้ยังคงไม่ระบุตัวตนแม้ตั้งโทเคนไว้ เพราะตอบเพียง `ok` และไม่มีอย่างอื่น

รหัสสิ้นสุด `3` สำหรับความล้มเหลวของสิทธิ์ใช้งาน `8` สำหรับต้นไม้ผลลัพธ์ที่ถูกล็อก `10` สำหรับการลบที่ไม่เคยยืนยัน และ `11` สำหรับการชนกันของการจับจอง จะขวางความพร้อมไว้โดยปริยาย เนื้อความของ `/ready` เป็น JSON เว้นแต่ผู้เรียกจะส่ง `Accept: text/plain` หรือเติม `?format=text`

## แดชบอร์ดและกฎการแจ้งเตือน

แดชบอร์ด Grafana สำเร็จรูปถูกเผยแพร่มาพร้อมไฟล์สำหรับติดตั้งในชื่อ `grafana-organize-files-automation.json` ภายใต้หัวเรื่อง **OrganizeFiles Automation** แผงทั้งสิบแสดงรอบตรวจที่ถึงกำหนด งานที่เริ่มและงานที่ล้มเหลว การชนกันของการจับจอง ปริมาณงานในหนึ่งชั่วโมง รหัสสิ้นสุดล่าสุด ความลึกของข้อความที่ส่งไม่สำเร็จ ความล้มเหลวของ webhook ในหนึ่งวัน งานที่รอการอนุมัติ และเหตุการณ์ของงานแยกตามสถานะ ทุกแผงระบุแหล่งข้อมูลของตนผ่านตัวยึด `${DS_PROMETHEUS}`

กฎการแจ้งเตือนที่คู่กันอยู่ใน `alerts-organize-files-automation.yaml` ส่วน `prometheus-rule-automation.yaml` เป็นเปลือก Kubernetes สำหรับ `kube-prometheus-stack` รหัสสิ้นสุดล่าสุดที่ไม่ใช่ศูนย์จะเตือนหลังห้านาที ความล้มเหลวของสิทธิ์ใช้งานถือว่าวิกฤติหลังหนึ่งนาที และกฎที่เหลือครอบคลุมงานที่ล้มเหลว การชนกันของการจับจอง ความล้มเหลวของ webhook การค้างของข้อความที่ส่งไม่สำเร็จ และการอนุมัติที่ถูกทิ้งให้รอหนึ่งวัน ไฟล์ทั้งสองถูกตรวจทุกครั้งที่สร้าง ชื่อข้างบนจึงเดินไปพร้อมกับตัวนับ

# เอาต์พุตการทำงานและเมตริก

## แถวสถานะ

พื้นที่ **เอาต์พุตการทำงาน** จะแสดง:

- สถานะปัจจุบันของแอปและความคืบหน้าของเอ็นจิ้น
- **CPU** และค่า **หน่วยความจำ** สองค่าสำหรับกระบวนการนี้เท่านั้น
- บรรทัด **GPU** บน Windows: ส่วนที่กระบวนการนี้ใช้จากการ์ดจอแต่ละใบ ไม่ใช่ทั้งการ์ด

แถบทรัพยากรขนาดกะทัดรัดเดียวกันนี้จะถูกนำมาใช้ซ้ำในหน้าต่างเครื่องมือรอง เช่น การสำรวจไฟล์ งานที่กำหนดเวลาไว้ และการซ่อมแซมไฟล์

## ป้ายหน่วยความจำ

- **ไบต์ส่วนตัว / คอมมิต** — หน่วยความจำเสมือนส่วนตัวที่สงวนไว้โดยกระบวนการ
- **ชุดการทำงาน / หน่วยความจำ** — RAM ประจำที่ปัจจุบันถือโดยกระบวนการนี้ ซึ่งอาจแตกต่างจากจอภาพระบบปฏิบัติการอื่นได้ เนื่องจากแต่ละระบบปฏิบัติการและสภาพแวดล้อมเดสก์ท็อปมีป้ายกำกับการประมวลผลหน่วยความจำแตกต่างกัน

## เรียกใช้ heartbeat JSON (ไม่บังคับ)

เปิดใช้งาน **Write run heartbeat JSON** ภายใต้ **ขั้นสูง / การวินิจฉัย** เอ็นจิ้นเขียน `Organize.Files.run.json` ใต้ `Output\_OrganizeMediaLogs` (โฟลเดอร์เดียวกับไฟล์จัดระเบียบไฟล์สถานะการรันต่อเริ่มต้น)

- **เส้นทาง** — อัปเดตแบบอะตอมมิกระหว่างการจัดระเบียบและการซ่อมแซม
- **ช่วงเวลาการเขียน** — ระหว่างสำรวจแหล่งที่มา ไฟล์จะถูกเขียนใหม่ทุก 10,000 ไฟล์ที่พบ ทุก 5,000 รายการที่ตรงกัน และราวทุก 15 วินาทีตราบที่การสำรวจยังดำเนินอยู่ ต้นไม้เครือข่ายขนาดใหญ่ที่แสดงรายการได้ช้าจึงยังแสดงให้เห็นว่าการรันยังทำงานอยู่ ระหว่างการตรวจสอบ การแฮช และการย้าย ไฟล์จะถูกเขียนใหม่หลังทุก 1,000 ไฟล์ และไม่ถี่กว่าทุก 5 วินาที ส่วนการเขียนตอนเริ่มและตอนจบยังคงเกิดขึ้นเมื่อการรันเริ่มต้นและสิ้นสุด
- **ความคืบหน้า** — ตราบใดที่จำนวนไฟล์ยังเพิ่มขึ้น แถบความคืบหน้าหลักจะแสดงจำนวนไฟล์ที่พบแล้วแทนที่จะเป็น 100% จนกว่าขั้นตอนนั้นจะมียอดรวมที่ทราบแน่ชัด
- **ช่อง** — `schema`, `mode`, `phase` (e.g. `enumerate`, `enumerate-done`, `classify`, `validate`, `move`, `done`), `runState` (`active` / `completed` / `failed` / `cancelled`), `utc` (ISO-8601), `dryRun`, `outputRoot`, `validateMedia`, `deepVideoValidate`, `gpuDeviceCount`, `hwaccel`, ตัวเลือก `correlationId`, ตัวนับ `progress` ที่ซ้อนกัน
- **บันทึก** — แผงเอาต์พุตการรันจะพิมพ์เส้นทางแบบเต็มเมื่อเริ่มต้นและเมื่อไฟล์ถูกบันทึกที่ตอนท้าย ใช้ **เปิดโฟลเดอร์บันทึกฮาร์ทบีท** / **แสดงไฟล์ JSON ฮาร์ทบีท** ภายใต้ขั้นสูง / การวินิจฉัย
- **CLI** — `--heartbeat-json` บน OrganizeFiles.Cli ข้อผิดพลาดการยกเลิกและเชลล์ร้ายแรงเขียน `cancelled` / `failed` `runState` เมื่อเปิดใช้งาน
