# Помічник AI (MCP)

Команди з ліцензією під'єднують **OrganizeFiles.Cli** до Claude Desktop, **Cursor**, VS Code Copilot або іншого клієнта Model Context Protocol, далі клієнта MCP. Конектор — це пакет Python **organize-files-mcp**. Його можна безкоштовно завантажити з github.com/GutRaz/organize-files-docs, з папки `mcp/`.

**У настільній програмі:** відкрийте **Налаштування MCP…** у групі **Додаток і дані** у стовпці параметрів або в меню інструментів. Виберіть **MCP доступ**: **Вимк.**, **Монітор** або **Контроль**. Потім скопіюйте фрагмент JSON. Після кожної зміни рівня перезавантажте MCP у програмі ШІ, бо **Контроль** щоразу створює новий токен.

**Запитайте помічника з документації** «setup mcp» або «cum setez mcp», щоб отримати кроки для поточної системи.

## Рівні доступу до MCP, задаються в програмі

Рівні відповідають трьом видам роботи: **читання / попередній перегляд / виконання**.

| Рівень | Вид роботи | Що може ШІ |
|-------|--------|-------------------|
| **Вимк.** | — | Лише `organize_mcp_status`. Немає діагностики й немає доступу до робочого простору. |
| **Монітор** | **Читання** | Усе, що є у Вимк., а також діагностика лише для читання, історія запусків і завдань, блокування, перевірки аудиту, **`organize_capabilities`** і **`organize_workspace_snapshot`**. `organize_capabilities` перелічує режими запуску, серед них **`ai`**, області переміщення й цілі. `organize_workspace_snapshot` показує робочий простір, збережений у головному вікні. Немає попереднього перегляду й немає виконання. |
| **Контроль** | **Попередній перегляд** / **Виконання** | Усе, що є в Монітор, а також **`organize_create_job`**, **`organize_run_workspace`** і **`organize_remove_empty_organize_layout`**. Потрібен **токен керування** в налаштуваннях MCP, `ORGANIZE_FILES_MCP_CONTROL_TOKEN`. **Попередній перегляд** — це `organize_run_workspace`, коли в збереженому робочому просторі ввімкнено **Пробний запуск**, тож нічого не записується. **Виконання** — той самий інструмент із вимкненим Пробним запуском, тож файли переміщуються. Конектор не передає `--confirm-destructive`, якщо виклик не задає `confirm_destructive=true`, а без цього прапорця командний рядок відмовляє з `confirm_destructive_required`. |

Файл керування — **`mcp-control.json`**, поруч із `automation-jobs.json` у папці профілю програми. Скопійований фрагмент його не називає, бо конектор знаходить файл у папці профілю за замовчуванням. Задавайте **`ORGANIZE_FILES_MCP_CONTROL_FILE`** лише тоді, коли файл лежить деінде. На рівні **Контроль** фрагмент також задає **`ORGANIZE_FILES_ALLOW_APP_TARGET=1`**.

**Переміщення й видалення потребують другого кроку, який робить людина.** Помічник сам ставить своє підтвердження, тож прочитаний текст міг би схилити помічника до підтвердження. Тому запуск, який не є пробним, потребує ще й вікна, відкритого в **Налаштування MCP**, і це вікно саме закривається через 15 хвилин. Поза вікном помічник і далі може підготувати запуск і показати попередній перегляд, але сам запуск відхиляється. І файл керування, і вікно підписані ключем цієї інсталяції. Файл керування, змінений вручну або скопійований з іншого комп'ютера, вважається рівнем Вимк.

## Інструменти MCP за рівнями

**Завжди, також на Вимк.:** `organize_mcp_status`

**Монітор і Контроль:** `organize_server_info`, `organize_cli_help`, `organize_query_runs`, `organize_show_run`, `organize_list_running`, `organize_query_jobs`, `organize_due_pass_lock_status`, `organize_output_lock_status`, `organize_verify_audit`, `organize_exit_code_guide` і `organize_run_raw_cli`, який приймає лише команди для читання.

**Також у Монітор і Контроль:** `organize_capabilities`, який показує режим запуску **`ai`** для файлів ШІ та машинного навчання, і `organize_workspace_snapshot`.

**Лише Контроль:** `organize_create_job` з робочого простору або з JSON завдання, `organize_run_workspace` для попереднього перегляду або справжнього запуску, як каже Пробний запуск робочого простору, і `organize_remove_empty_organize_layout`, який видаляє порожні папки розкладки всередині наявної папки виводу й ніколи не створює саму папку виводу.

Команди, які переміщують або видаляють файли, через MCP завжди заблоковані поза рівнем **Контроль**. Жодне інше налаштування їх не дозволяє.

## Прапорці командного рядка, які використовує конектор

| Прапорець | Рівень | Призначення |
|------|-------|---------|
| `--mcp-control-status` | будь-який | JSON із рівнем, шляхом до файлу керування та прапорцями Монітор і Контроль |
| `--mcp-capabilities` | Монітор і вище | Список JSON із режимами запуску, серед них **`ai`**, областями переміщення й цілями |
| `--mcp-workspace-snapshot` | Монітор і вище | Збережений робочий простір і те, як він стає завданням |
| `--mcp-create-job` | Контроль | Створити завдання з `--from-workspace` або `--mcp-job-json` |
| `--mcp-run-workspace` | Контроль | Запустити збережений робочий простір з `--allow-app-target` і `--mcp-control-token` |
| `--remove-empty-organize-layout` | Контроль | Видалити порожні папки розкладки всередині наявного `--output` |
| `--confirm-destructive` | Контроль | Потрібен із `--mcp-run-workspace` для запуску, який переміщує або видаляє. Конектор передає його лише за `confirm_destructive=true` |

## Налаштування в JSON клієнта MCP

| Налаштування | Коли |
|----------|------|
| `ORGANIZE_FILES_CLI` | Шлях до OrganizeFiles.Cli |
| `ORGANIZE_FILES_JOBS_FILE` | Шлях до `automation-jobs.json` |
| `ORGANIZE_FILES_MCP_CONTROL_FILE` | Шлях до `mcp-control.json`, лише якщо файл не в папці профілю за замовчуванням |
| `ORGANIZE_FILES_MCP_CONTROL_TOKEN` | Лише рівень **Контроль**, із фрагмента програми |
| `ORGANIZE_FILES_ALLOW_APP_TARGET` | Рівень **Контроль**, для запусків збереженого робочого простору |
| `ORGANIZE_FILES_MCP_READ_TOKEN` | Необов'язково. Той самий токен, який хост використовує для операцій читання |

## Налаштування у Windows

1. **Python 3.10 або новіший** — виконайте `python -V` у PowerShell. Якщо Python немає або версія старша, установіть його з [python.org](https://www.python.org/downloads/) і позначте **Add python.exe to PATH**.
2. **Завантажте й установіть конектор** — завантажте github.com/GutRaz/organize-files-docs як ZIP, розпакуйте й запустіть `powershell -ExecutionPolicy Bypass -File mcp\Install-OrganizeFilesMcp.ps1`. Скрипт створює окреме середовище Python для конектора й виводить команду для програми ШІ.
3. **У програмі:** **Налаштування MCP…**, виберіть **Монітор** або **Контроль**, потім скопіюйте JSON.
4. **Шляхи:** у `%LocalAppData%\OrganizeFilesCrossPlatform\` лежать завдання й `mcp-control.json`. Cursor: `%USERPROFILE%\.cursor\mcp.json`. Claude: `%APPDATA%\Claude\claude_desktop_config.json`. VS Code: `%USERPROFILE%\.vscode\mcp.json`.
5. **Перевірка** — виконайте `organize_mcp_status`, потім `organize_server_info`. `cliResolved` має бути true, а `mcpLevel` має збігатися з програмою.

## Налаштування в macOS

Ті самі кроки з **python3** і `bash mcp/install-organize-files-mcp.sh`. Якщо `python3 -V` показує 3.9 або Python немає зовсім, спершу установіть Python з [python.org](https://www.python.org/downloads/macos/). Шляхи: `~/Library/Application Support/OrganizeFilesCrossPlatform/`, `~/.cursor/mcp.json`, Claude `~/Library/Application Support/Claude/claude_desktop_config.json`.

## Налаштування в Linux

Ті самі кроки з **python3** і `bash mcp/install-organize-files-mcp.sh`. У Debian і Ubuntu спершу виконайте `sudo apt install python3-venv`. Шляхи: `~/.local/share/OrganizeFilesCrossPlatform/`, або `$XDG_DATA_HOME`, якщо його задано, `~/.cursor/mcp.json`, Claude `~/.config/Claude/claude_desktop_config.json`.

## Безпека

- MCP працює від імені **локального користувача** операційної системи, з тими самими правами, що й командний рядок, запущений вручну.
- Тримайте **токен керування** й **токен читання** в секреті, як паролі. Скопіюйте JSON знову після ввімкнення рівня Контроль.
- **`organize_run_workspace`** працює в командному рядку, а не через кнопку Запустити в програмі. Не запускайте два завдання на ту саму папку виводу одночасно.
- Приклади: `mcp/examples/`.

## Запуски, які переміщують або видаляють

`--mcp-run-workspace` вимагає `--confirm-destructive` для кожного запуску, який не є пробним, чи то переміщення, видалення, чи архівування. Без цього прапорця командний рядок відповідає `confirm_destructive_required`. Конектор не передає прапорець, якщо виклик не задає `confirm_destructive=true`, а це може лише рівень Контроль. Тож за замовчуванням конектор відмовляє.

## Мови

Відповіді про налаштування беруться з того самого перекладеного посібника, що й вікно Документація та Помічник із довідки. `organize_capabilities` повідомляє режими запуску й цілі, а не назви тем програми.
